# Gold-Standard Briefs — README for downstream agent developers

This directory is the export surface for **agentic audit-coverage briefs** produced by the meta-audit pipeline. Each project subdirectory (e.g. `swell/`, `aave/`, `lido/`) contains the per-project artifacts.

We've started a parallel reference set under the name **"gold standard"** so you can compare what the pipeline currently produces against what a correct, manually-researched brief looks like.

## File naming convention inside each project directory

| File | Origin | What it is |
|---|---|---|
| `brief.md` | Pipeline (exporter v2) | Generated by the meta-audit pipeline. May be wrong, incomplete, or contaminated — see `_gold_standard.md` for the same project to see how. |
| `manifest.json` | Pipeline | Machine-readable structural data backing `brief.md`. Same caveat — the manifest reflects whatever the pipeline produced, defects and all. |
| `onchain_tvl.json` | Pipeline | DL-snapshot TVL number used by the brief. |
| `SCOPE_NOTE.md` | Pipeline | Operator-facing notes on scope-match status. |
| `contracts/{chain}/...` | Pipeline | Per-contract source code cache that the pipeline pulled from Etherscan. |
| `brief_gold_standard.md` | **Manual research** | Reference brief produced by reading DefiLlama + the project's own docs + GitHub + Etherscan, with no pipeline involvement. This is what a correct brief should look like. |
| `manifest_gold_standard.json` | **Manual research** | Same schema intent as `manifest.json`, but with verified data: per-contract role classification, audit→contract mapping, product-line decomposition, explicit "this contract is NOT part of the project" exclusions where the v1 pipeline mis-attributed, and explicit "missing from v1" entries where the pipeline missed a real contract. |

A diff between `brief.md` and `brief_gold_standard.md` (and likewise the two manifests) is a defect map for the pipeline. The accompanying internal trace lives at `docs/gold-standard/{project}_v1_diff_analysis.md` in the meta-audit repo and walks each divergence back to a specific pipeline stage.

## Why we're publishing both

Two reasons.

**1. We want to know what's actually missing for your agent.** The pipeline-generated brief is what we ship today. The gold-standard brief is what we'd ship if every stage worked correctly. If you build an audit-targeting agent on top of either of these, please tell us:

- Which fields does your agent actually consume?
- Which fields are missing or under-specified?
- Which fields, when wrong, break your agent's downstream behavior the most?
- Is the per-product-line decomposition (e.g. swell-lst / swell-lrt / swell-btc-lrt / swell-earn) more useful than a single flat scope inventory? Or do you want both?
- Does the explicit `excluded_from_scope` list (with attribution evidence) help your agent reason about what NOT to scope?
- Is JSON or markdown more useful for your code path?

**2. We want a stable target to optimize against.** Until we have a manually verified reference, any pipeline metric we compute against the v1 output is self-referential. The gold standard gives the verifier (and any reviewers) an external anchor that is independent of the pipeline's own beliefs.

- Other projects — not yet covered. We expect to add gold-standard pairs for ~5–10 high-value projects (Aave, Lido, Pendle, EigenLayer, Curve, Compound, Uniswap, etc.) before treating this as a benchmark set.

## What "gold standard" does NOT mean

- It does not mean the brief is operator-confirmed. Multisig membership, ProxyAdmin owners, timelock duration, governance-gate parameters are explicitly out of scope here. Those require operator interview.
- It does not mean every audit→contract mapping has been validated by reading the PDF cover-to-cover. Mappings are reconstructed from filenames + product-line context. Where uncertainty exists, the gold-standard brief flags it.
- It does not mean the contract list is exhaustive of every Swell-deployed-ever contract on every chain. It is the audit-evaluable surface: contracts holding user funds on the chains DefiLlama enumerates, plus first-order operational periphery and bridge stack.

## Reporting feedback

If you're a downstream agent developer comparing the two briefs, please open a discussion / issue / DM with one or more of:

- A specific field that is missing from `manifest_gold_standard.json` that your agent needs.
- A specific field that's present but in a format your agent can't consume.
- A specific divergence from `brief.md` to `brief_gold_standard.md` that your agent would have surfaced (or failed to surface) in production.
- A request for additional projects to receive the gold-standard treatment.

The goal is to converge `brief.md` toward `brief_gold_standard.md`. Your feedback shapes what we prioritize.
